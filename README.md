# 추자초 5학년 말바당 사전 — 배포용 프로젝트

Claude 미리보기에서 만든 `jeju-dictionary-app.jsx`를 실제 인터넷에 배포할 수 있는
React(Vite) 프로젝트로 옮기고, 저장소를 Firebase Firestore로 교체한 버전이에요.

## 1. Firebase 프로젝트 만들기 (딱 한 번만 하면 돼요)

1. https://console.firebase.google.com 접속 → 구글 계정으로 로그인
2. "프로젝트 추가" → 이름 입력(예: jeju-dictionary) → Google Analytics는 꺼도 됨 → 프로젝트 생성
3. 왼쪽 메뉴 "빌드 > Firestore Database" → "데이터베이스 만들기" → 위치는 asia-northeast3(서울) 선택 →
   처음에는 "테스트 모드"로 시작(30일간 누구나 읽기/쓰기 가능, 나중에 보안 규칙을 손볼 수 있어요)
4. 왼쪽 상단 톱니바퀴 "프로젝트 설정" → 맨 아래 "내 앱" → 웹 아이콘(`</>`) 클릭 → 앱 닉네임 아무거나 입력 → 등록
5. 화면에 뜨는 `firebaseConfig` 객체의 값들을 복사해둬요. 예시:
   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "jeju-dictionary.firebaseapp.com",
     projectId: "jeju-dictionary",
     storageBucket: "jeju-dictionary.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abcdef",
   };
   ```

## 2. 이 프로젝트에 설정값 넣기

1. 이 폴더에서 `.env.example` 파일을 복사해서 `.env` 파일을 만들어요.
2. `.env` 파일을 열어서 방금 복사한 값들을 하나씩 채워넣어요.
   ```
   VITE_FIREBASE_API_KEY=AIzaSy...
   VITE_FIREBASE_AUTH_DOMAIN=jeju-dictionary.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=jeju-dictionary
   VITE_FIREBASE_STORAGE_BUCKET=jeju-dictionary.appspot.com
   VITE_FIREBASE_MESSAGING_SENDER_ID=123456789
   VITE_FIREBASE_APP_ID=1:123456789:web:abcdef
   ```
   (`.env`는 `.gitignore`에 이미 포함돼 있어서 GitHub에는 올라가지 않아요. 대신 Vercel에 배포할 때
   같은 값들을 Vercel의 "Environment Variables"에 한 번 더 입력해줘야 해요.)

## 3. 로컬에서 실행해보기

터미널(명령 프롬프트)에서 이 폴더로 이동한 뒤:

```bash
npm install
npm run dev
```

터미널에 뜨는 주소(보통 http://localhost:5173)를 브라우저로 열어서
낱말 등록, 이미지 첨부, 음성 녹음, 관리자 승인까지 한 번씩 테스트해보세요.
문제없이 되면 Firebase 콘솔의 Firestore Database에도 `words`, `wordMedia`, `meta` 컬렉션이 자동으로 생기는 걸 확인할 수 있어요.

## 4. GitHub에 올리고 Vercel로 배포하기

```bash
git init
git add .
git commit -m "제주말 사전 배포 준비"
```

GitHub에서 새 저장소를 만든 뒤 안내에 따라 `git remote add origin ...` 하고 `git push -u origin main`.

그 다음 https://vercel.com 에서 GitHub 계정으로 로그인 → "Add New Project" → 방금 만든 저장소 선택 →
"Environment Variables"에 `.env`에 적었던 값들을 똑같이 하나씩 입력 → Deploy.

몇 분 뒤 `https://프로젝트이름.vercel.app` 같은 실제 주소가 생기고,
이후로는 GitHub에 push할 때마다 자동으로 다시 배포돼요.

## 알아두면 좋은 점

- **관리자 PIN**: 지금은 코드에 `0640`이 그대로 적혀있는 데모용이에요. 공개 배포 전에
  `src/App.jsx`의 `ADMIN_PIN` 값을 바꾸거나, 별도 로그인 방식으로 교체하는 걸 권장해요.
- **이미지·음성 용량 제한**: Firestore 문서 하나는 최대 1MB까지만 저장할 수 있어요.
  그래서 이 버전은 Claude 미리보기 버전보다 이미지(약 500KB)·음성(각 200KB) 제한을 줄여뒀어요.
  나중에 더 큰 파일을 다루고 싶으면 Firebase Storage(유료 Blaze 요금제 필요) 또는
  Cloudinary 같은 이미지 호스팅 서비스로 옮기는 걸 고려해보세요. (Claude 미리보기 안에서는
  샌드박스 제한 때문에 이런 외부 업로드가 막히지만, 실제 배포된 사이트에서는 정상 작동해요.)
- **Firestore 보안 규칙**: "테스트 모드"는 30일 후 자동으로 잠겨요. 계속 쓰려면 Firebase 콘솔의
  Firestore Database > 규칙 탭에서 기간을 연장하거나 규칙을 다시 설정해야 해요.
- **닉네임 저장 방식**: "등록자 닉네임"은 각자 기기(브라우저)에만 저장돼요(localStorage). 다른
  기기로 접속하면 다시 입력해야 해요.
- **불러오는 속도 최적화**: 낱말의 글자 정보(`words` 컬렉션)와 이미지·음성(`wordMedia` 컬렉션)을
  분리해서 저장해요. 사전 목록·검색·정렬 화면은 가벼운 글자 정보만 불러오고, 이미지·음성은
  낱말 상세 페이지를 열 때만 그때그때 불러오기 때문에 사전에 낱말이 많이 쌓여도 처음 들어갈 때
  느려지지 않아요. (브라우저 로컬 캐시 기능은 저장 성공 여부를 화면에서 확인하기 어렵게 만들어서
  뺐어요 — 등록·수정할 때마다 실제 서버와 바로 통신해서, 실패하면 화면에 바로 에러가 떠요.)
- **저장·불러오기 에러 확인**: 등록/수정/삭제가 실패하면 화면 위에 빨간 배너로 에러 메시지가
  떠요. 그 문구가 원인을 알려주니, 문제가 생기면 그 문구를 그대로 확인해보세요.
- **Vercel 환경변수 값에 따옴표를 넣지 마세요**: Firebase 콘솔의 `firebaseConfig` 예시를 그대로
  복사하면 `projectId: "jeju-dictionary",`처럼 따옴표와 쉼표가 같이 붙어있어요. Vercel의
  Environment Variables에는 따옴표 없이 `jeju-dictionary`만 입력해야 해요. (따옴표가 섞여
  들어가면 사이트가 "불러오는 중..."에서 멈추고 콘솔에 에러도 안 뜨는 채로 조용히 실패해요.)
  값을 수정한 뒤에는 꼭 Vercel의 "Deployments" 탭에서 **Redeploy**까지 해야 반영돼요.

## 낱말 · 표현 · 속담 (2번째 업데이트)

- **낱말 등록**: 지금까지처럼 표준어/제주어/추자생활언어를 나란히 등록해요.
- **표현 등록**: 메뉴의 "표현 등록" 탭에서 제주어 또는 추자생활언어 중 하나를 골라 문장 하나와
  그 뜻을 등록해요. 이미지·음성은 선택 사항이에요. 등록된 표현은 낱말과 마찬가지로 관리자 승인을
  거쳐 사전에 실리고, 사전 화면에서 "전체 함께보기 / 낱말만 모아보기 / 표현만 모아보기"로 골라볼
  수 있어요.
- **제주어 속담**: 사용자가 등록하는 게 아니라, 관리자 페이지의 "속담 관리" 탭에서 승인 절차 없이
  바로 추가·수정·삭제해요. 오늘의 낱말처럼 홈 화면에 "오늘의 속담"으로 매일 하나씩 노출되고,
  새로고침 버튼으로 다른 속담을 바로 볼 수 있어요.
- **닉네임 규칙**: 닉네임은 낱말/표현을 처음 등록할 때만 입력해요. 이후 "수정 제안"이나 관리자
  수정에서는 닉네임을 다시 묻지 않고, 최초 등록자 이름은 그대로 유지돼요. (수정한 사람은 각자
  기기에 저장된 닉네임으로 "최근 수정" 기록에만 남아요.)
- **숨김 처리**: 관리자 페이지의 "전체 콘텐츠 관리" 탭에서 이미 승인된 낱말·표현을 "숨기기" 할 수
  있어요. 숨긴 항목은 일반 사전 화면에서는 보이지 않고 관리자 페이지에서만 "숨김" 표시와 함께
  계속 확인할 수 있으며, "숨김 해제"를 누르면 다시 사전에 노출돼요. (완전히 지우는 삭제와는 달라요.)
- **페이지 나누기**: 사전 화면과 관리자 페이지의 "전체 콘텐츠 관리" 탭은 한 번에 20개씩만 보여주고
  아래쪽 "이전/다음" 버튼으로 페이지를 넘겨요.
- **새로고침 없이 바로 반영**: 등록·수정·승인·숨김 처리 등은 모두 화면(브라우저) 상태를 먼저
  바꾸고 나서 Firestore에 저장하기 때문에, 다른 탭으로 이동해도 새로고침 없이 바로 최신 내용이
  보여요. (다만 저장이 실패하면 빨간 에러 배너가 뜨니 꼭 확인해주세요.)

### Firestore 컬렉션 구조 (참고용)

- `words`: 낱말과 표현이 함께 들어있어요. 각 문서는 `kind` 필드로 `'word'`(낱말) 또는
  `'expression'`(표현)을 구분하고, `hidden` 필드로 숨김 여부를 나타내요. (예전에 만든 낱말
  문서에는 `kind`/`hidden` 필드가 없을 수 있는데, 앱에서는 이걸 자동으로 `word`/`false`로
  취급하니 따로 손보지 않아도 돼요.)
- `wordMedia`: 기존과 동일하게 이미지·음성만 낱말/표현 id별로 저장해요.
- `proverbs`: 제주어 속담을 저장하는 새 컬렉션이에요. (`jeju`, `meaning` 필드)
- `meta`: `today`(오늘의 낱말)에 더해 `todayProverb`(오늘의 속담) 문서가 추가됐어요.

## 중복 경고 · 카드 PDF · 오늘의 퀴즈 (3번째 업데이트)

- **중복 등록 경고**: "단어 등록"/"표현 등록"에서 [등록 신청하기]를 눌렀을 때, 사전에 이미 실려 있는
  같은 표준어(낱말) 또는 같은 문장(표현)이 있으면 "똑같은 낱말/표현이 이미 사전에 등록되어 있습니다…"
  확인 창이 떠요. [취소]를 누르면 입력한 내용이 그대로 남고, [무시하고 신청하기]를 누르면 신청돼요.
  무시하고 신청한 항목은 관리자 "승인 대기" 목록에 **⚠ 중복된 낱말/표현** 표시가 붙어요.
  (숨김 처리된 항목과 승인 대기 중인 항목은 "이미 등록됨"으로 보지 않아요.)
- **낱말/표현 카드 만들기 (PDF)**: 상세 페이지의 [낱말/표현 카드 만들기 (PDF)] 버튼으로 1장,
  사전 목록의 체크박스로 여러 장을 한 번에 만들어요. 카드 크기는 64mm×89mm이고, 1장이면 카드 크기
  그대로, 여러 장이면 A4 한 쪽에 잘리지 않게 최대인 9장(3×3)씩 배치해요. 카드는 "바다 친구들" 초록 디자인(물결 머리띠·점선 말풍선)이고, 이미지, 표준어/
  제주어/추자생활언어, 예문이 들어가요. (PDF는 브라우저 안에서 만들어서 서버나 새 라이브러리가 필요 없어요.)
- **오늘의 퀴즈**: 사전 낱말로 하루 한 문제를 내요. 표준어가 아닌 말(제주어·추자생활언어 등)과 예문을
  보여주고 표준어를 3개 보기 중에서 고르게 해요. 매일 한국 시간 0시에 문제가 바뀌고, 이미 푼 사람이
  다시 들어오면 "이미 오늘의 퀴즈를 완료하였습니다."와 함께 푼 문제를 보여줘요. 풀고 나면 정답과
  [사전에서 찾아보기] 버튼이 나와요. 낱말(표준어)이 3개 미만이면 퀴즈가 열리지 않아요.
  - **같은 사람 구분 기준**: `src/quiz.js` 맨 위 `QUIZ_LIMIT_BY`. 기본 `'device'`(기기·브라우저별로 하루 한 번).
    같은 기기라도 다른 브라우저나 시크릿 창이면 다시 풀 수 있어요. `'ip'`(접속 IP 기준)로 바꿀 수도 있지만,
    학교 와이파이처럼 모두가 같은 IP를 쓰면 학교 전체에서 한 명만 풀 수 있어요.
  - 새 Firestore 컬렉션: `meta/quizToday`(오늘 문제), `quizAttempts`(참여 기록, 문서 id `날짜_사용자키`).
    "테스트 모드" 규칙이면 별도 설정 없이 동작해요.

## 카드 짝맞추기 · 관리자 입구 변경 (4번째 업데이트)

- **카드 짝맞추기** (메뉴 "짝맞추기"): 사전에 실린 낱말 중 표준어·제주어가 모두 있는 낱말로 해요.
  인원(1~4명)과 낱말 수(8·10·12·15개 → 카드 16·20·24·30장)를 고르고 시작해요.
  1명은 모든 짝을 맞출 때까지 걸린 시간을 재고, 2~4명은 짝을 맞추면 계속하고 틀리면 다음 사람에게
  넘어가며 가장 많이 맞춘 사람이 이겨요(동점이면 공동 우승/무승부). 맞춘 카드는 플레이어별 색(1P 파랑,
  2P 분홍, 3P 노랑, 4P 보라)과 번호표로 구분돼요. 같은 글자가 겹치는 낱말은 한쪽만 쓰고,
  쓸 수 있는 낱말이 선택한 수보다 적으면 그 선택지는 눌러지지 않아요. (게임 기록은 저장하지 않아요.)
- **관리자 입구**: 위쪽 메뉴에서 "관리자" 탭을 없앴어요. 화면 맨 아래
  "이 사전은 이용자들이 함께 채워가는 열린 사전이에요." 문구를 클릭하면 관리자 PIN 화면으로 가요.
  (마우스를 올려도 링크처럼 보이지 않아요.) 스마트폰에서는 카드 수에 맞춰 열 수와 카드 크기가 자동으로 줄어서 한 화면에 들어와요.

## 5차 수정: 아래아(ᆞ) 입력 버튼 + 글꼴

- **아래아 버튼**: `제주어 낱말`, `제주어 예문`, `제주어 표현 문장` 입력창 아래에 "ㆍ 아래아 넣기" 버튼이 나타나요. (낱말/표현 수정 폼은 같은 폼을 쓰므로 관리자 수정, 이용자 '수정 제안'에도 함께 나와요.)
- **글꼴**: `public/fonts/araea-400.woff`(보통), `araea-700.woff`(굵게) (Noto Sans CJK KR 한글 자모 부분집합, OFL). 아래아가 있는 글자(자모 U+1100–11FF 등)에만 쓰이고, 그때만 내려받아요(약 170KB).
- **입력 처리**: `src/jejuInput.js` — 자음 + ᆞ를 첫가끝 조합으로 만들고, 뒤따르는 자음은 받침으로 붙여요. 저장할 때 `finalizeAraea`로 한 번 더 정리해요.
- **한계**: 기기 키보드(IME) 특성상 아래아 뒤 받침 자음은 다음 글자를 입력하거나 입력창을 벗어날 때 합쳐져요. 아래아 낱말의 검색·정렬 보정과 기존 데이터 변환은 하지 않았어요.

## 6차 수정: 글꼴 통일
- 웹앱 전체 글꼴을 본고딕(Noto Sans KR) **보통(400)/굵게(700)** 두 가지로 통일했어요. 제목·낱말·버튼·탭 등 강조는 굵게, 설명·본문은 보통이에요. (기존 Jua 글꼴과 500/900 굵기는 없앴어요.)
- 아래아가 들어간 글자는 같은 굵기의 `Araea` 글꼴(본고딕 자모 부분집합)로 자동으로 보여요. 카드 PDF도 동일해요.
- 삭제된 파일: `public/fonts/araea-900.woff` (→ `araea-700.woff`로 교체)

## 7차 수정: 아래아 입력 안내
- 아래아 버튼 옆 `?` 버튼을 누르면 "아래아 밑에 받침을 넣을 때는 받침 자음을 누르고 커서를 다른 곳으로 옮기세요." 한 줄이 펼쳐져요. (`AraeaButton`, `.araea-*` 스타일)
- 관리자 '문장 관리'(오늘의 문장)의 제주어 문장 입력창(새로 추가·수정)에도 아래아 버튼을 넣었어요.
- 메인 화면 오늘의 문장 박스 아래에 속담 출처(제주특별자치도) 문구를 작은 회색 글씨로 넣었어요. (`.source-note`)
- 관리자 페이지 낱말 목록에 정렬 선택(등록순=최신순 / 표준어 가나다순)을 넣었어요. 표현은 문장 기준으로 가나다순에 섞여요.

## 8차 수정: 메뉴 정리
- 아래아 `?` 안내 문구를 "아래아 밑에 받침을 넣을 때는 받침 자음을 누르고 커서를 다른 곳으로 옮기세요."로 변경.
- 메뉴 이름: `퀴즈` → `오늘의 퀴즈`, `사전` → `사전 둘러보기`.
- `단어 등록`/`표현 등록` 메뉴를 `사전 등록` 하나로 통합. 화면 맨 위 가운데의 '낱말 등록 / 표현 등록' 선택 탭으로 고르고, 기본은 낱말 등록이에요. (`RegisterHub`)
- 상단 제목('추자초 5학년 말바당 사전')을 누르면 홈으로 이동해요.

## 9차 수정: 쌍아래아(ᆢ)
- 아래아 버튼을 연속으로 두 번 누르면 쌍아래아(U+11A2)로 바뀌어요. (`src/jejuInput.js`, 아래아 바로 뒤에서만 동작하고 세 번째부터는 무시해요.)
- 쌍아래아 뒤의 받침도 아래아와 똑같이 처리돼요. 글꼴(`araea-*.woff`)에 쌍아래아 글자가 들어 있어요.

## 10차 수정: 낱말 입력 칸 정렬
- 표준어/제주어/추자생활언어 3칸이 바깥 테두리를 넘던 문제를 고쳤어요. 입력칸 기본 너비 때문에 3칸이 칸 너비보다 커져서 생기던 문제라, 3칸을 같은 너비(`minmax(0, 1fr)`)로 맞추고 입력칸이 칸 안에서만 늘어나게 했어요. 720px 이하에서는 세로로 한 줄씩 쌓여요.

## 11차 수정: 보안(관리자 이메일 로그인 + Firestore 규칙)
- 테스트 모드 종료(30일)에 맞춰 관리자 PIN을 없애고 **Firebase 인증(이메일/비밀번호)** 로그인으로 바꿨어요. 관리자 화면에 로그아웃 버튼이 있어요.
- `firestore.rules` 추가: 일반 이용자는 승인된 낱말만 읽고, 신청(승인 대기)·댓글만 쓸 수 있어요. 승인/수정/삭제/숨김/문장 관리는 관리자만 가능해요.
- 일반 이용자의 낱말 조회는 `status == approved` 조건으로 해요. 관리자는 로그인 후 승인 대기까지 불러와요.
- 이미지·음성 저장 순서를 이미지·음성 → 글자 정보로 바꿨어요.
- 버그 수정: 댓글 추가·삭제, 숨김 처리 때 이미지·음성이 빈 값으로 덮어써질 수 있던 문제를 막았어요. (`dbSaveWordCore`)
- **설정 순서는 `보안설정-가이드.md`를 따라주세요.**
- 버그 수정: 관리자가 이미지·음성을 수정·저장해도 화면에 예전 값이 남아 있던 문제(캐시 미갱신)를 고쳤어요.
- 관리자 승인 대기 목록에 체크박스와 일괄 처리(선택 승인 / 선택 반려, 전체 선택, 중복 표시 제외하고 선택)를 넣었어요. 일괄 반려는 한 번 더 확인해요.
- 숫자 확인용 표시: 메인(낱말 N개 · 표현 N개), 사전 둘러보기 위(낱말/표현 수 + 필터·검색 중 현재 목록 수), 관리자 전체 콘텐츠 관리 위(공개 낱말 · 표현 · 숨김 = 전체).
